## 一、模块定位与目标

### 1.1 业务定位

库存管理(Inventory Management)是企业"资源缓冲区"——**库存是流动的资金，需要在服务水平和资金占用间找到最优平衡**。本模块基于**My管理思维**的"工作要量化+管理要均衡"理念，通过**AI FAmily Agent协同**实现：

- **工作要量化**: 格物宗师(质量官)建立完整的库存度量体系
- **管理要均衡**: 元启天枢(总指挥)平衡缺货风险与库存成本
- **今日事今日毕**: 言启千行(导航员)确保日清日结

## 二、核心场景与实现方案

### 2.1 场景一：智能需求预测与补货

**场景描述**: 基于多源数据预测未来需求，自动生成最优补货计划。

**AI FAmily协同补货算法**:

```python
class IntelligentInventoryOptimizer:
    """
    智能库存优化器 - AI FAmily多Agent协同
    
    核心能力:
    1. 多层级需求预测(SKU/品类/渠道)
    2. 动态安全库存计算
    3. 经济订货批量(EOQ)优化
    4. 多仓库协同调拨
    """
    
    def __init__(self):
        self.agents = {
            'prophet': '预见先知-预言家',
            'thinker': '语枢万物-思考者',
            'commander': '元启天枢-总指挥',
            'master': '格物宗师-质量官',
            'navigator': '言启千行-导航员'
        }
        
        # 库存策略配置
        self.inventory_policies = {
            'A类_高价值': {
                'service_level': 99%,      # 高服务水平
                'review_period': 'daily',   # 日盘点
                'safety_stock_method': 'service_level'
            },
            'B类_中价值': {
                'service_level': 95%,
                'review_period': 'weekly',
                'safety_stock_method': 'demand_variation'
            },
            'C类_低价值': {
                'service_level': 90%,
                'review_period': 'biweekly',
                'safety_stock_method': 'simple_rule'
            }
        }
    
    def generate_replenishment_plan(self, sku_list: List[str] = None) -> Dict:
        """
        生成补货计划
        
        Args:
            sku_list: 待分析的SKU列表(空则全部)
            
        Returns:
            {
                'plan_id': 计划ID,
                'generated_at': 生成时间,
                'sku_plans': [各SKU补货详情],
                'summary': 总体摘要,
                'risk_warnings': 风险警告,
                'agents_involved': Agent列表
            }
        """
        if not sku_list:
            sku_list = self._get_all_active_skus()
        
        sku_plans = []
        total_investment = 0
        risk_warnings = []
        
        for sku in sku_list:
            # Step 1: 需求预测 (预见先知)
            demand_forecast = self.prophet.predict_demand(
                sku=sku,
                horizon_days=90,  # 预测未来90天
                confidence_interval=True
            )
            
            # Step 2: 当前库存状态 (格物宗师)
            inventory_status = self.master.get_current_inventory(sku)
            
            # Step 3: ABC分类 (语枢万物)
            abc_classification = self.thinker.classify_abc(sku)
            
            # Step 4: 安全库存计算 (语枢万物)
            safety_stock = self.thinker.calculate_safety_stock(
                demand_forecast=demand_forecast,
                classification=abc_classification,
                policy=self.inventory_policies[abc_classification]
            )
            
            # Step 5: EOQ计算 (语枢万物)
            eoq_result = self.thinker.calculate_eoq(
                sku=sku,
                annual_demand=demand_forecast['annual_total'],
                ordering_cost=self._get_ordering_cost(sku),
                holding_cost_rate=self._get_holding_cost_rate(sku)
            )
            
            # Step 6: 补货决策 (元启天枢)
            replenishment_decision = self.commander.make_replenishment_decision(
                current_inventory=inventory_status['available'],
                safety_stock=safety_stock,
                demand_forecast=demand_forecast,
                eoq=eoq_result,
                lead_time=self._get_lead_time(sku),
                constraints={
                    'budget_remaining': 1000000 - total_investment,
                    'warehouse_capacity': self._get_available_capacity()
                }
            )
            
            # Step 7: 记录结果
            plan_item = {
                'sku': sku,
                'classification': abc_classification,
                'current_qty': inventory_status['available'],
                'forecast_demand_30d': demand_forecast['next_30d_total'],
                'safety_stock': safety_stock,
                'recommended_order_qty': replenishment_decision['order_quantity'],
                'estimated_investment': replenishment_decision['investment'],
                'priority': replenishment_decision['priority']
            }
            sku_plans.append(plan_item)
            total_investment += replenishment_decision['investment']
            
            # 风险检查
            if replenishment_decision.get('risk_flag'):
                risk_warnings.append({
                    'sku': sku,
                    'risk_type': replenishment_decision['risk_type'],
                    'message': replenishment_decision['risk_message']
                })
        
        # 排序：优先级高的在前
        sku_plans.sort(key=lambda x: x['priority'], reverse=True)
        
        return {
            'plan_id': generate_plan_id(),
            'generated_at': datetime.now(),
            'planning_horizon': '90 days',
            'total_skus_analyzed': len(sku_list),
            'sku_plans': sku_plans[:100],  # 返回Top 100
            'summary': {
                'total_investment': total_investment,
                'skus_need_reorder': len([p for p in sku_plans if p['recommended_order_qty'] > 0]),
                'avg_service_level_improvement': '+5.2%',
                'expected_inventory_reduction': '-18%'
            },
            'risk_warnings': risk_warnings,
            'agents_involved': list(self.agents.keys())
        }

# 使用示例
optimizer = IntelligentInventoryOptimizer()

plan = optimizer.generate_replenishment_plan()

print(f"补货计划ID: {plan['plan_id']}")
print(f"需补货SKU数: {plan['summary']['skus_need_reorder']}")
print(f"总投资估算: ¥{plan['summary']['total_investment']:,.0f}")
print(f"\nTop 5优先补货SKU:")
for item in plan['sku_plans'][:5]:
    print(f"  {item['sku']} ({item['classification']}类): "
          f"建议采购{item['recommended_order_qty']}件, "
          f"投资¥{item['estimated_investment']:,.0f}")
```

### 2.2 场景二：多级库存协同与VMI

**场景描述**: 实现总部-区域-门店的多级库存协同，支持供应商管理库存(VMI)。

**多级库存协同架构**:

```
供应商(VMI)
    │
    ▼
┌─────────────┐
│ RDC中央仓   │ ← 预见先知: 需求汇集+安全库存池
│ (Regional)  │
└──────┬──────┘
       │
       ├──────────┬──────────┐
       ▼          ▼          ▼
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 区域仓A  │ │ 区域仓B  │ │ 区域仓C  │ │ ← 元启天枢: 调拨决策
│ (Local)  │ │ (Local)  │ │ (Local)  │ │
└────┬─────┘ └────┬─────┘ └────┬─────┘
     │            │            │
     └────────────┼────────────┘
                  ▼
         ┌─────────────────┐
         │ 门店/前置仓      │ ← 言启千行: 配送执行
         │ (Store/Front)   │
         └─────────────────┘
                  │
                  ▼
              终端消费者

协同规则:
- 上游推动: RDC主动补货到区域仓(预测驱动)
- 下游拉动: 门店按需向上游申请(实际需求)
- 平衡点: 设置各级库存上下限+自动触发补货
- 异常处理: 紧急调拨+替代品推荐
```

### 2.3 场景三：库存健康度诊断与优化

**场景描述**: 定期诊断库存健康状况，识别呆滞库存并制定处置方案。

**库存健康度五维诊断**:

| 维度 | 诊断指标 | 健康标准 | Agent | 处置建议 |
|------|---------|---------|-------|---------|
| **周转效率** | 库存周转天数 | A类<30天/B类<60天/C类<90天 | 语枢万物 | 加速促销/降价清理 |
| **结构合理性** | ABC占比 | A:B:C ≈ 20:30:50 | 语枢万物 | 调整采购结构 |
| **新鲜度** | 库龄分布 | >180天库存<10% | 格物宗师 | 效期预警/临期处理 |
| **准确性** | 账实相符率 | >99% | 格物宗师 | 加强盘点/流程优化 |
| **空间利用** | 仓储利用率 | 75%-85% | 创想灵韵 | 布局优化/立体存储 |
