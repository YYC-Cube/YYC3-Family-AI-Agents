# 提示词工程编写规范 v1.0

## 定位

**YYC³ 提示词工程统一编写规范**，基于 CO-STAR + CRAFT 双框架，覆盖提示词的全生命周期管理。

## 核心理念

**五高架构**: 高可用 | 高性能 | 高安全 | 高扩展 | 高智能
**五标体系**: 标准化 | 规范化 | 自动化 | 可视化 | 智能化
**五化转型**: 流程化 | 数字化 | 生态化 | 工具化 | 服务化

## 一、CO-STAR 框架

### 1.1 框架概览

CO-STAR 是 2026 年提示词工程的事实标准框架（来源：PromptQuorum 2026），定义提示词必须包含的六大要素：

```
┌─────────────────────────────────────────────────────────────────┐
│                      CO-STAR 框架结构                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   C — Context (背景)                                             │
│   ├── 提供任务背景信息                                           │
│   ├── 说明相关约束条件                                           │
│   └── 描述当前状态和环境                                         │
│                                                                 │
│   O — Objective (目标)                                           │
│   ├── 明确期望达成的结果                                         │
│   ├── 定义成功的衡量标准                                         │
│   └── 设定优先级和取舍规则                                       │
│                                                                 │
│   S — Scope (范围)                                               │
│   ├── 界定任务边界                                               │
│   ├── 明确不在范围内的内容                                       │
│   └── 定义深度和广度要求                                         │
│                                                                 │
│   T — Task (任务)                                                │
│   ├── 具体要执行的操作                                           │
│   ├── 步骤和子任务分解                                           │
│   └── 输入数据和格式要求                                         │
│                                                                 │
│   A — Audience (受众)                                            │
│   ├── 目标读者/用户群体                                          │
│   ├── 知识水平和专业背景                                         │
│   └── 期望的交互风格和语气                                       │
│                                                                 │
│   R — Response (响应)                                            │
│   ├── 期望的输出格式                                             │
│   ├── 结构要求和示例                                             │
│   └── 质量标准与约束                                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 CO-STAR 模板

```markdown
# Identity (身份设定)
你是 [角色名称]，[角色描述]。你拥有 [专业背景/经验]。
你的风格：[交互风格描述]。

# Context (背景)
[当前场景描述]
[相关约束条件]
[已有信息/数据]

# Objective (目标)
[核心目标]
[成功标准]
[优先级说明]

# Scope (范围)
[在范围内的内容]
[不在范围内的内容]
[深度/广度要求]

# Task (任务)
请按以下步骤执行：
1. [步骤1]
2. [步骤2]
3. [步骤3]

# Audience (受众)
[目标用户]
[知识水平]
[期望风格]

# Response (响应格式)
[输出格式]
[结构要求]
[质量标准]
[示例参考]
```

### 1.3 CO-STAR 评分标准

| 要素 | 权重 | 0分 | 1分 | 2分 | 3分 |
|------|------|-----|-----|-----|-----|
| **Context** | 15% | 无背景 | 简略背景 | 明确背景 | 丰富背景+约束 |
| **Objective** | 20% | 无目标 | 模糊目标 | 明确目标 | 目标+成功标准 |
| **Scope** | 10% | 无范围 | 隐式范围 | 显式范围 | 范围+边界 |
| **Task** | 25% | 无步骤 | 简单步骤 | 结构化步骤 | 步骤+子任务+依赖 |
| **Audience** | 10% | 无受众 | 简略受众 | 明确受众 | 受众+风格适配 |
| **Response** | 20% | 无格式 | 简略格式 | 具体格式 | 格式+示例+约束 |

**通过标准**: 总分 ≥ 80% (≥ 2.4/3.0 平均分)

## 二、CRAFT 框架

### 2.1 框架概览

CRAFT 是 2026 年提示词工程的结构化交付框架，强调提示词的工程化、可复用、可评测：

```
┌─────────────────────────────────────────────────────────────────┐
│                      CRAFT 框架结构                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   C — Clear (清晰)                                               │
│   ├── 语言精准，无歧义                                           │
│   ├── 逻辑结构清晰可读                                           │
│   └── 关键信息突出标记                                           │
│                                                                 │
│   R — Reusable (可复用)                                          │
│   ├── 参数化设计，支持变量替换                                   │
│   ├── 模块化组合，场景可拼接                                     │
│   └── 版本化管理，可追溯变更                                     │
│                                                                 │
│   A — Aligned (对齐)                                             │
│   ├── 与业务目标对齐                                             │
│   ├── 与安全合规对齐                                             │
│   └── 与AI Family角色对齐                                       │
│                                                                 │
│   F — Functional (功能化)                                        │
│   ├── 可执行，产出确定                                           │
│   ├── 可测试，效果可验证                                         │
│   └── 可监控，指标可追踪                                         │
│                                                                 │
│   T — Testable (可测试)                                          │
│   ├── 有明确的测试用例                                           │
│   ├── 有量化的效果指标                                           │
│   └── 有回归测试机制                                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 CRAFT 与 CO-STAR 的关系

```
CO-STAR (内容框架)          CRAFT (质量框架)
─────────────────────────────────────────────────
Context (背景)    ────────► Aligned (对齐)
Objective (目标)  ────────► Aligned (对齐)
Scope (范围)      ────────► Clear (清晰)
Task (任务)       ────────► Functional (功能化)
Audience (受众)   ────────► Clear (清晰)
Response (响应)   ────────► Functional (功能化)
                  ────────► Reusable (可复用)
                  ────────► Testable (可测试)
```

### 2.3 CRAFT 评分标准

| 维度 | 权重 | 检查项 | 通过标准 |
|------|------|--------|---------|
| **Clear** | 25% | 无歧义、逻辑清晰、关键信息突出 | 新手可正确理解 |
| **Reusable** | 20% | 参数化、模块化、版本化 | 3个场景可复用 |
| **Aligned** | 20% | 与业务/安全/角色对齐 | 无越权/违规 |
| **Functional** | 20% | 可执行、产出确定 | 5次运行一致 |
| **Testable** | 15% | 有测试用例、有指标、有回归 | 自动化测试通过 |

## 四、YYC³ Agent 提示词编写规范

### 4.1 通用规则

1. **身份优先**: 所有提示词以 `# Identity` 开头，明确角色设定
2. **安全内置**: 所有提示词必须包含安全约束（见1209-安全合规与伦理治理）
3. **CO-STAR 结构**: 所有提示词必须包含六大要素
4. **参数化**: 使用 `{{变量名}}` 标识可替换参数
5. **版本标注**: 所有提示词标注版本号和更新日期
6. **语言一致**: 中文场景使用中文提示词，英文场景使用英文提示词
7. **标记规范**: 重要结论用🎯，风险点用⚠️，创新点用💡，待确认用❓
8. **响应优先**: 优先使用结构化格式（JSON/Markdown/表格），避免纯文本

### 4.2 角色特定规范

| Agent | 角色 | 提示词特点 | 关键约束 |
|-------|------|-----------|---------|
| 元启天枢 | 总指挥 | 结构化决策框架、多Agent协调 | 不做越权决策、需人类确认关键决策 |
| 言启千行 | 导航员 | 意图分类、路由规则 | 不能编造信息、错误时承认并重试 |
| 语枢万物 | 思考者 | 数据分析步骤、统计方法 | 数据来源标注、不能假设数据 |
| 预见先知 | 预言家 | 预测模型、不确定性量化 | 必须标注置信区间、不能绝对化预测 |
| 千里伯乐 | 推荐官 | 个性化推荐、学习路径 | 避免偏见、保护隐私 |
| 智云守护 | 安全官 | 安全检查、审计规则 | 保持中立、不执行业务操作 |
| 格物宗师 | 质量官 | 质量标准、评测方法 | 客观公正、不偏袒任何Agent |
| 创想灵韵 | 创意官 | 创意生成、风格适配 | 不抄袭、标注参考来源 |

### 4.3 上下文工程最佳实践

```
2026年提示词工程已从「模板时代」进入「上下文工程」时代。

上下文工程四大支柱:
├── 1. 系统提示词 (System Prompt)
│   ├── 角色设定 + 安全约束 + 行为规则
│   ├── 缓存策略: 高频不变部分单独缓存
│   └── 长度控制: 不超过总上下文的30%
│
├── 2. 检索增强 (RAG - Retrieval-Augmented Generation)
│   ├── 企业知识库: 产品文档/流程规范/历史案例
│   ├── 实时数据: 经营数据/市场动态/行业报告
│   └── 检索策略: 语义检索 + 关键词检索混合
│
├── 3. 少样本示例 (Few-shot Examples)
│   ├── 2-3个高质量示例 > 10个普通示例
│   ├── 正例+反例: 展示正确的和错误的做法
│   └── 动态选择: 根据任务类型自动选择相关示例
│
└── 4. 对话历史 (Conversation History)
    ├── 滑动窗口: 保留最近N轮对话
    ├── 摘要压缩: 超长对话自动摘要
    └── 记忆检索: 关键信息持久化存储
```
