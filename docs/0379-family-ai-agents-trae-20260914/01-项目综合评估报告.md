## 三、多维审计

### 3.1 🔴 P0 — 治理身份映射断裂（本次评估最重大发现）

**证据链**：
- 治理中枢注册短名：`AGENTS = ["tianshu","qianxing",...,"bole","shouhu","zongshi","lingyun"]`（governance_hub.py L36）
- 生产容器上报全名：`AGENT_NAME: zhiyu_bole`（docker-compose.yml L269，8 个服务同理 `yuanqi_tianshu` 等）
- 失效传导：
  - **Kill Switch/冻结失效**：agent_server `_check_frozen` 以 `zhiyu_bole` 查询 → hub `agent_state` 表只有 `bole` 行 → **永不命中冻结**（L70-L77 vs hub L671-L677）
  - **预算失效**：`record_usage("zhiyu_bole")` → `self._budgets.get()` 未命中 → 返回 error，**Token 预算对全部 8 家人不生效**（hub L347-L352）
  - **协同失效**：`should_collaborate("zhiyu_bole")` → 无规则匹配 → 永不触发协同
  - **ACS 政策错位**：`generate_all()` 遍历短名 AGENTS，而 ACS config 键是 `main/research/...` 第三套命名 → 全部回落 manual
- **佐证**：compose 中 `AGENT_PHONE: 0379-0206` 等身份字段存在但服务代码未使用——身份体系半接入

**影响**：治理中枢五大能力中审计（记录仍写入但 agent 字段为全名，trail 可查）之外，冻结/预算/协同/ACS 四项在生产环境静默失效。
**修复建议**（三选一，推荐 A）：
- A. hub 增加 `ALIAS_MAP = {full_name: short_name}` 归一化入口（单点收敛，兼容两侧）
- B. compose `AGENT_NAME` 改短名（改 8 处 env + systemd override）
- C. hub AGENTS 改全名（改 DEFAULT_BUDGETS/RULES/FALLBACK 4 处 + 已有 DB 行迁移）
**回归保障**：tests/integration/test_endpoints.py::TestGovernanceAgentNameContract 已固化该契约，修复后改断言即可。

### 3.2 🔴 P0 — 端点零认证

- 全部 25 个 hub 端点 + 5 个 agent 端点无任何认证（kill-switch 可被任意内网调用一键冻结全员，agent_server.py `host="0.0.0.0"` 暴露所有网卡）
- 内网专用网络（172.29.0.0/16）为仅有的隔离层；host 端口映射 25700/25600-25607 全部 0.0.0.0 发布
- **修复**：复用 `examples/13-YYC3-企业蓝图-代码示例/1307-代码示例-安全合规/zero_trust_gateway.py`（已实现 API-Key 校验 + 权限类别五维映射）；至少对 kill-switch/unfreeze/budget reset 加写保护

### 3.3 ⚠️ P1 — 安全与健壮性细节

| 项 | 证据 | 建议 |
| ---- | ---- | ---- |
| 敏感数据明文入审计 | `chat_request` 记录 `message[:100]`（agent_server L124）——用户消息可能含密钥 | 脱敏后再入库（复用 hub `_assess_risk` 敏感词表） |
| **风险升级早返回缺陷** | `_assess_risk` 对 DANGEROUS_ACTIONS 早返回，敏感关键词升级被绕过——**本次测试发现并已修复**（hub L223-L236），回归测试固化 | ✅ 已修复 |
| SQLite 跨进程并发 | systemd 直跑 hub + compose 也可跑 hub，双实例共写 /data/governance.db 无 WAL | 启用 `PRAGMA journal_mode=WAL` + 部署互斥说明 |
| compose 内 pip install | 每次容器启动 `pip install --quiet flask requests`（L73 等）——不可复现构建 + 启动慢 | 构建自有镜像或挂 wheel |
| /identity 信息泄露 | 返回 IDENTITY.md 全文（agent_server L204-L214）——未认证下暴露人设资产 | P0 认证解决后自然收敛 |
| chromadb/profile_router 懒加载 | hub 内 `import chromadb`/`from profile_router import` 无依赖声明（requirements.txt 无 chromadb） | 依赖补全或可选依赖标注 |

### 3.4 性能审计

| 项 | 现状 | 评估 |
| ---- | ---- | ---- |
| 每请求治理开销 | /chat 串行 4 次治理 HTTP（frozen→context→collab + 2 次上报），每次 timeout 2-3s | 🟡 最坏叠加 ~10s；建议并行化或本地缓存 frozen 状态（30s TTL） |
| SQLite 每事件一连接 | auditor.record 每次新建连接 | 🟡 建议连接池或线程本地连接 |
| 资源限制 | 仅 hub 有 limits（1C/1G），8 Agent 无限制 | 🟡 单 Agent 失控可拖垮宿主 |
| 预算重置 | reset-daily 仅手动端点，无 cron/systemd timer | 🟡 长期运行将永远不重置 → 全员触发 block |

### 5.2 错误模式分析（代码级）

| 模式 | 出现位置 | 频次 | 风险 |
| ---- | ---- | ---- | ---- |
| 裸 `except Exception: pass` | agent_server 治理上报 5 处 | 5 | 中——故障静默不可见；建议至少 logger.debug |
| `get_json(force=True)` | hub 25 端点全量 | 25 | 低——但畸形 JSON 会 500 而非 400 |
