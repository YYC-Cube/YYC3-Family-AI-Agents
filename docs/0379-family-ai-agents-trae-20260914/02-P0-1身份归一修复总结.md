# 🔧 P0-1 身份归一修复总结

> **一句话**：生产容器以全名（`zhiyu_bole`）上报、治理中枢以短名（`bole`）存储，导致 Kill Switch / Token 预算 / 协同触发 / ACS 政策四项治理能力对全部 8 位家人**生产静默失效**；通过 hub 侧 `AGENT_ALIAS_MAP` 单点收敛修复，九入口双向归一，契约测试固化，36/36 全绿。
>
> **提交**：`cfd23e8`（修复 + 契约测试 + 总结衔接）｜ 后续 `c719f48`（诊断清零，行号已刷新）

## 一、问题（发现于五领域综合评估）

### 1.1 根因：身份词表三分裂

同一家人在系统内存在三套命名，互不匹配：

| 来源 | 命名体系 | 示例 |
| ---- | ---- | ---- |
| `docker-compose.yml` / systemd（生产容器） | 全名 `AGENT_NAME` | `yuanqi_tianshu`、`zhiyu_bole`、`chuangxiang_lingyun` |
| 治理中枢内部注册表（[governance_hub.py:37](file:///Users/yanyu/YYC-Cube/YYC3-Family-AI-Agents/governance_hub.py#L37)） | 短名 `AGENTS` | `tianshu`、`bole`、`lingyun` |
| ACS 政策配置 `AGENT_ACS_CONFIG` | 角色名 | `main`、`research`、`creative` |

### 1.2 失效传导链（修复前）

```
agent_server 上报 AGENT_NAME="zhiyu_bole"
        ↓
hub 以 "zhiyu_bole" 查 agent_state / _budgets / COLLABORATION_RULES
        ↓ 短名表无此键
① _check_frozen 永不命中   → Kill Switch 冻结对全名 Agent 无效
② record_usage 返回 error  → Token 预算对全部 8 家人不生效
③ should_collaborate 无匹配 → 协同触发永不发生
④ generate_all 遍历短名     → ACS 政策与实际容器身份错位，全部回落 manual
```

**风险定级 P0 的依据**：治理中枢的核心卖点（审计之外的主动干预能力）在生产环境全部失效，且**无任何报错**（治理上报为静默旁路设计）——故障不可见。

### 1.3 发现方式

综合评估集成测试 `TestGovernanceAgentNameContract` 固化短名/全名漂移现状时确认为真实缺陷（先固化为已知问题，后转正为修复验收）。

## 二、修复方案

### 2.1 方案选型（三选一）

| 方案 | 改动面 | 回滚成本 | 结论 |
| ---- | ---- | ---- | ---- |
| **A. hub 侧别名归一** | 仅 hub 1 文件 | 最低（删映射即回滚） | ✅ **采纳** |
| B. compose 改短名 | 8 服务 env + systemd override + 已运行容器 | 高 | ❌ |
| C. hub 改全名 | AGENTS/DEFAULT_BUDGETS/RULES/FALLBACK 4 处 + SQLite 存量行迁移 | 高 | ❌ |

**采纳 A 的决定性理由**：零生产 env 改动（容器无需重建）、SQLite 存量短名行无需迁移、DB 写入侧归一保证存储层单一事实。

### 2.2 实现要点

**① 唯一映射源**（[governance_hub.py:39-52](file:///Users/yanyu/YYC-Cube/YYC3-Family-AI-Agents/governance_hub.py#L39-L52)）：

```python
AGENT_ALIAS_MAP = {
    "yuanqi_tianshu": "tianshu",
    "yanqi_qianhang": "qianxing",
    "yushu_wanwu": "wanwu",
    "yujian_xianzhi": "xianzhi",
    "zhiyu_bole": "bole",
    "zhiyun_shouhu": "shouhu",
    "gewu_zongshi": "zongshi",
    "chuangxiang_lingyun": "lingyun",
}

def normalize_agent(name: str) -> str:
    """全名/短名归一为 hub 内部短名（未知名原样返回，由调用方决定策略）"""
    return AGENT_ALIAS_MAP.get(name, name)
```

## 四、运维注意事项（重要）

### 4.1 三处联动纪律（新增/更名家人时）

```
① docker-compose.yml / systemd override 的 AGENT_NAME（全名）
② governance_hub.py AGENT_ALIAS_MAP（全名→短名映射）+ AGENTS（短名注册）
③ tests/integration/test_endpoints.py TestGovernanceAgentNameContract.FULL_TO_SHORT（测试侧事实源）
```

> 三处任一不同步，对应家人的治理能力将静默失效（与本次 P0 同构）。
> **演进建议**：后续可将该映射外置为 `agents/registry.json` 单一事实源，hub/compose/tests 三方消费，彻底消除联动纪律依赖（P2）。

### 4.2 已知边界

- `normalize_agent` 对未知名**原样返回**（宽容策略）：首次接入新家人时治理记录会以全名落库，直到映射补全——不会报错但需留意 trail 中出现全名行即为「映射未同步」信号
- `agent_server` 侧 `_check_frozen` 查询使用自身 `AGENT_NAME`，已被 hub 读入口归一覆盖，无需改动
